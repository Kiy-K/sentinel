**Concept 1 — "Night Shift" — a personal on-call engineer agent**
**Pitch:** Your production web app gets a pager that pages a person only when it's actually down, and fixes the boring stuff itself.

**What it does:** You point it at your app's repo and health endpoints. On a schedule and on Slack/GitHub webhooks, it wakes (hibernation), pulls the repo, reproduces the failure in a sandboxed run, opens a PR with a fix + regression test, comments on the incident, and only escalates to you (Slack DM) when confidence is low or data is at risk. Every action is journaled to a checkpointed run log you can replay.

**Sprites fit:** Hibernation wake-on-request is the demo — the sprite sleeps at $0 until a webhook or schedule hits its URL, wakes in seconds, works, sleeps. Checkpoints let it roll back a bad fix. GitHub OAuth connector means the sprite never sees a raw token; AgentMail gives it its own inbox for incident comms. Sandbox = full Linux, so it can actually run the app's test suite, not just guess.

**60s demo:** Kill the healthcheck on a toy app → webhook fires → sprite wakes (show `fly` dashboard sleeping→awake) → it clones, reproduces, patches, runs tests green, posts PR + Slack message → back to sleep. Timer on screen.

**Feasibility:** Med-High. Riskiest piece: reliable failure reproduction for arbitrary apps — mitigate by demoing on a curated example app, not "any repo."

**Originality 7/10, Wow 8/10.** Prize lane: main track ($2500) — Fly engineers are exactly this ICP; reliability-first framing plays to them.

**Concept 2 — "The Receipts Clerk" — a personal finance/admin agent that closes your books**
**Pitch:** Forward any email receipt; the agent files, categorizes, dedups, and drafts your monthly expense report.

**What it does:** AgentMail inbox receives receipts/invoices. Agent extracts line items (LLM + rules), dedups against card transactions you paste/export, categorizes, stores in a local SQLite ledger on the sprite, and monthly drafts a report + drafts a reply to "can you send me the receipt for X?" via email. Human-in-the-loop: nothing sends without your ✅ in Slack.

**Sprites fit:** Persistent SQLite on the sprite = real memory, not a stateless chat wrapper. AgentMail connector keeps mail credentials out of the sprite; Slack connector for approvals; hibernation = it's free until mail arrives (webhook wake). Checkpoint before every write batch → "undo my last 3 filings."

**60s demo:** Forward 3 receipts live → sprite wakes → extraction table appears → dedup catches a double-listed charge → Slack approval card → ✅ → report PDF + ledger query shown.

**Feasibility:** High. Riskiest piece: extraction accuracy on messy receipts — keep to email-body/PDF text, not photos.

**Originality 6/10, Wow 7/10.** Prize lane: $1500 — useful, demonstrable, slightly less flashy. Strong backup pick.

**Concept 3 — "Sentry Parrot" — a personal watchdog for the small-print internet**
**Pitch:** An agent that watches the 40 pages you never check — ToS changes, price drops, gov deadlines, domain expiry — and pings you only on material change.

**What it does:** You subscribe URLs with intents ("alert me if the cancellation policy gets worse", "if this fin tariff drops below X"). Sprite wakes on schedule, Firecrawl scrapes, diffs against stored snapshots, LLM judges materiality, and posts a one-line verdict + diff to Slack/email. Keeps a full versioned snapshot history (checkpointable).

**Sprites fit:** Scheduled wake + hibernation is the whole economic story (agent costs ~0 when nothing changes). Firecrawl + Slack connectors; S3/Tigris for snapshot archive. Persistent disk = real diffing, which stateless cron+LLM can't do cleanly.

**60s demo:** Pre-seed a watched page; live-edit the page (or use a toggle endpoint) to change the ToS cancellation clause → watch agent wake, detect, judge "material," post Slack alert with the exact clause diff. Then show 3 weeks of "no change" silence as the feature.

**Feasibility:** High. Riskiest piece: LLM materiality judgment consistency — mitigate with strict structured output + a rubric and show it catching a real clause change.

**Originality 7/10, Wow 6/10.** Prize lane: $1000/$2500 depending on polish; strong demo clarity. Good "Weird Uncle" alternate if pushed weird.

**Concept 4 — "Dead Man's Switch, But Useful" — a personal legacy/ops agent**
**Pitch:** An agent that holds your digital contingency playbook and executes it only if you go silent.

**What it does:** You write runbooks (pay rent, cancel subscriptions, notify people, hand over 2FA-recovery info locations, deploy a static memorial page). Agent does a daily liveness check-in (email/Slack "√"). After N missed check-ins + configurable escalation ladder (remind → trusted contact → execute runbook), it acts: emails your designated contacts with prepared letters, renews/cancels services via prepared scripts, sets the site live. Everything staged in checkpoints; you can rehearse in "dry-run" mode anytime.

**Sprites fit:** This is the killer use case for hibernation + persistence: a thing that must exist for years, cost nothing, and wake reliably on a heartbeat. Checkpointing = rehearsal/dry-run safety. AgentMail (sends letters), Slack (check-ins), Neon or sprite-local SQLite (state machine), Resend optional. Credentials via connectors, never in sprite.

**60s demo:** Show the state machine; simulate 3 missed check-ins live; watch it send the rehearsed notification to a second inbox you control; then "disarm" instantly by checking in. Emotionally resonant, technically crisp.

**Feasibility:** Med-High. Riskiest piece: judgment about not-falsely-triggering in the demo — solve by explicit "demo mode" with a 30-second timer; be blunt that real-world timing is config, not code.

**Originality 9/10, Wow 9/10.** Prize lane: main track or Weird Uncle — the "agent with a dead-man's heartbeat" framing is memorable and genuinely useful.

**Rejected: "AI personal CFO that negotiates your bills/haggles over phone via ElevenLabs voice."** Tempting — voice demo is flashy. Rejected: (1) telephony + voice latency flakes on stage in 5 days; (2) weak engineering signal for Fly judges — it's a thin wrapper over a voice API, no sprite-specific value beyond hosting; (3) liability/scope creep. The judged axis is engineering merit + reliability, and this demos worst exactly when the network is bad.

**Ranking:** Concept 1 for pure prize odds (Fly's audience, crisp loop); Concept 4 if you want to be remembered; Concept 2 if you want the safest High-feasibility ship. All four use hibernation + connectors meaningfully rather than as decoration.
